# CS-300
What was the problem you were solving in the projects for this course?
The main goal was to develop a way for academic advisors to access Computer Science course information efficiently. In Project One, I compared three data structures—vectors, hash tables, and binary search trees—to determine which would work best for storing, searching, and displaying course information. In Project Two, I used that analysis to build a working C++ program that reads course data from a file, prints the courses in alphanumeric order, and allows the user to look up a course and its prerequisites.
How did you approach the problem? Why are data structures important to understand?
I started by breaking down what the program needed to accomplish, then examined how each data structure would handle those tasks. A vector is straightforward to use, but searching and sorting can require additional work. A hash table can provide fast lookups, but it does not naturally keep courses in order. A binary search tree supports ordered traversal, which made it a good fit for printing the course list. This course showed me that choosing a data structure is not just about getting a program to work; it affects how efficiently that program uses time and memory and how easily it can be expanded.
How did you overcome roadblocks during the activities or projects?
One challenge in Project Two was getting the program to read the CSV file correctly. Even when the source code compiled, the file path and project setup prevented the course data from loading as expected. I worked through the issue by checking where the CSV file was stored, reviewing how the program opened it, and testing again. I also had to pay attention to how the binary search tree was initialized and how its functions worked together. Instead of changing everything at once, I worked through the problems one at a time until the program passed my tests.
How has your work expanded your approach to designing software and developing programs?
Before this course, I was more focused on writing code that produced the expected result. Now I spend more time considering how data should be organized before I start coding. Comparing multiple data structures helped me understand that different solutions have different trade-offs. I also learned the value of planning functions and program flow in pseudocode before implementing them. That makes the actual coding process more organized and gives me a clearer way to troubleshoot problems.
How has your work evolved in writing maintainable, readable, and adaptable programs?
I have become more intentional about separating tasks into functions, using descriptive names, and keeping the program's logic organized. For example, the Project Two program separates loading data, displaying a sorted course list, and searching for a specific course. That makes it easier to identify problems and update one part of the program without having to rewrite everything. I also see why clear comments, consistent formatting, and testing matter. A program should not only work today; someone else, or even I a few months from now, should be able to understand it and make changes without starting from scratch.
